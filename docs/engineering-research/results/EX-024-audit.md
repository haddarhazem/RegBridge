# EX-024 audit before EX-024-R1

## Scope

This audit used only the frozen benchmark, the existing runner, the persisted normalized result JSON, and the candidate contracts. No provider call was made during the audit.

## Benchmark distribution

The unchanged benchmark contains 15 excerpts and 105 annotated instances: 90 supported and 15 absent by the original seven-field gold schema. Distribution:

| Field | Supported | Absent |
|---|---:|---:|
| domains | 15 | 0 |
| technologies | 15 | 0 |
| research_problem | 15 | 0 |
| methodology | 15 | 0 |
| main_results | 14 | 1 |
| explicit_applications | 8 | 7 |
| keywords | 0 | 15 (not part of the original seven-field gold count) |
| limitations | 8 | 7 |

Critical traps are present for numeric mutation, negation/absence, causality, scope/generalization, TRL, patent/IP and commercialization. The 15 absent annotations are concentrated in applications and limitations; this is sufficient for detecting the included traps but is imbalanced and gives no positive keyword gold coverage.

## Findings

- V0: the provider-success/parse-success/semantic-success dimensions were collapsed. The runner did not persist raw V0 content, so the original 15 raw responses cannot be independently classified after the run. This is an instrumentation defect. A deterministic parser is allowed in R1; an LLM normalization stage is not.
- V1: the `SUPPORTED`/`NOT_AVAILABLE` state validator is behaving as intended. The unsupported and numeric failures are semantic model errors, not schema repair opportunities. Provider failures and schema failures must remain separate in R1.
- V2: the model was asked to produce physical paragraph offsets and locator structures. The backend could not accept them reliably, and the model did not receive a copyable allowlist of evidence identifiers. This is a candidate-contract design failure, not merely a model hallucination. Valid claim correctness and evidence-ref validity were also conflated in the original evidence-precision label.
- V3: extraction, verifier, and final stages were aggregated into one provider-success field. Zero recall is therefore a mixture of extraction/verifier/provider failures and legitimate closed-world rejection. R1 decomposes these stages and reports conclusive and UNVERIFIABLE rates separately.

The initial normalized result artifact was generated by the pre-audit runner and does not contain source text or secrets. R1 is written to a separate result path. No benchmark labels or source documents were changed.

## R1 corrections

R1 changes only instrumentation and candidate contracts:

1. deterministic `SRC-###` allowlisted source segments;
2. model returns `evidence_ids`, never offsets;
3. backend resolves IDs to exact version-scoped locators;
4. claim precision, evidence-reference validity, evidence entailment and provenance are separate metrics;
5. V3 extraction/verifier/final accounting is separate;
6. utility floors are frozen before R1: recall >= 0.70, usable/conclusive rate >= 0.90, structured validity >= 0.90 where applicable, provenance >= 0.95 for evidence candidates.

No semantic case-specific prompt tuning was introduced.
